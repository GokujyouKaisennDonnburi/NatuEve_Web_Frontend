# ADR-0007: 取りやめ済みのイベント詳細ページは noindex にし、構造化データの `EventCancelled` は使わない

- ステータス: Superseded by ADR-0008
- 日付: 2026-11-26
- 関連: #471, #375, NatuEve_API#311, NatuEve_API ADR-0054

## コンテキストと課題

NatuEve_API ADR-0054 により、一覧系の API と sitemap 用の API は取りやめ済みのイベントを返さなくなった。
詳細 API（`GET /api/v1/events/{id}`）は、取りやめの通知メールや共有リンクの受け皿として、取りやめ済みも `cancelledAt` を付けて返す。

sitemap から外しても、すでに検索結果に載ったページは消えない。共有リンクなどからたどられて、新しく載ることもある。
取りやめ済みのイベントを検索に残すか、外すかを決める必要がある。

制約と前提は次のとおり。

1. **構造化データはまだない**（#375 が Open）。検索結果に残しても、中止は検索エンジンに伝わらない。
2. **詳細ページは取りやめを表示していない**。`EventDetail.tsx` は `cancelledAt` を見ていない（表示は #471 の範囲外）。
3. **取りやめが削除の代わりに使われる**。イベントを削除する機能がなく、テストやスパムのイベントも取りやめで片付ける（NatuEve_API ADR-0054）。
4. **`noindex` と `EventCancelled` は両立しない**。`noindex` のページは検索結果に出ないため、構造化データで中止を伝えても使われない。

## 決定

**取りやめ済みのイベント（詳細 API の `cancelledAt` が `null` 以外）の詳細ページ `/event/[id]` に `noindex` を付ける。構造化データ（#375）で `EventCancelled` を出して中止を伝える方法は使わない。**

1. `buildEventMetadata`（`src/utils/seo.ts`）で、`cancelledAt` があるときだけ `robots: { index: false }` を返す。他の noindex のページ（`/coming-soon` など）と同じく `follow` は残す。
2. 取りやめていないイベントの詳細ページには `robots` を付けない。
3. `robots.txt` で詳細ページを `Disallow` にしない。クロールされないと `noindex` が読まれない。
4. 見直し: 詳細ページで取りやめを表示し、#375 で構造化データを入れるときに、`EventCancelled` で検索結果に残すほうがよいかを見直す。

## 理由

- **検索から来た人に取りやめが伝わらない**: 構造化データも詳細ページの表示もないため、検索から来た人は中止を知らずに申し込もうとし、`409` で初めて分かる。
- **片付けたイベントを検索に残さない**: 取りやめたテストやスパムのイベントを検索エンジンに伝え続けるのは、片付けた目的と逆になる。
- **sitemap の方針とそろう**: NatuEve_API ADR-0054 で sitemap から外した。詳細ページを `noindex` にすると、検索エンジンへの伝え方が一致する。
- **直リンクは使えるままにする**: `404` にはせず、通知メールや共有リンクから来た人はこれまでどおりページを開ける。

## 影響（結果）

### 良い影響
- 取りやめ済みのイベントが、検索エンジンが再訪したときに検索結果から外れる。
- 共有リンクなどからたどられても、新しく検索結果に載らない。

### トレードオフ・制約
- 検索結果から外れるのは検索エンジンが再訪したとき。Google は、Googlebot が再訪するまで数か月かかることがあるとしている（[Block Search indexing with noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing)）。
- 取りやめたイベントを検索した人には、中止したことが検索結果で伝わらない。
- #375 では、取りやめ済みのイベントに `EventCancelled` を出しても検索結果には使われない。

## 検討した代替案

- **`EventCancelled` を出して検索結果に残す**: 構造化データも詳細ページの表示もまだなく、中止が伝わらない。テストやスパムのイベントも残る / 不採用（決定 4 で見直す）
- **取りやめ済みの詳細ページを `404` にする**: 通知メールや共有リンクから来た人が、取りやめたことを知れない。詳細 API も返している / 不採用
- **`robots.txt` で `Disallow` にする**: クロールされず `noindex` も読まれないため、すでに載ったページが消えない。URL に取りやめの有無も出ない / 不採用
- **`noindex, nofollow` にする**: 検索結果から外すには `noindex` で足り、リンクをたどらせない理由はない。nofollow にしているのは、確認トークンを URL に含む `/events/[id]/join/confirm` だけである / 不採用
